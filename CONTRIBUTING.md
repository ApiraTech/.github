# Contributing

Thank you for helping improve an ApiraTech project. Repository-specific instructions take
precedence over this organization-wide guide.

## Before starting

1. Search existing issues and pull requests for related work.
2. For a substantial change, open an issue first so maintainers can confirm the scope and design.
3. For a security vulnerability, follow [SECURITY.md](SECURITY.md) instead of opening a public
   issue.

## Making a change

1. Fork or branch from the repository's default branch.
2. Keep the change focused and follow the repository's existing style.
3. Add or update tests and documentation when behavior changes.
4. Run the repository's documented checks locally.
5. Open a pull request using the repository's template and explain both the change and how it was
   validated.

Maintainers may ask for revisions or decline changes that do not fit the project's direction.
By participating, you agree to follow our [Code of Conduct](CODE_OF_CONDUCT.md).
